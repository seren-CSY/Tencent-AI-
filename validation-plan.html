内部评审用 · 系统化验证方案

「让用户放心把 AI 文稿用于正式场合」—— 创作体验验证方案

被测对象：DeckSure「想法 → 成稿 → 用户逐项确认 → 定稿上会」整条创作体验。本方案与用户定位页同源：核心命题不是「生成得快」，而是「生成+确认之后，用户敢不敢直接拿去正式场合，现场被问住也不会出丑」。

统一场景：售前顾问 Sasha · 面向跨国零售集团的 30 分钟商业价值汇报 判定对象：可放心度 主线：对外正式汇报（英文） 最大待验证模块：事实与数据校验引擎
总览 · 怎么组织这份方案

判定逻辑一句话看懂的入口

「可放心用于正式场合」无法由单一内部指标推出，因此按三件套组织：① 评测体系（分端到端与子能力两层，各给目标、通过线与 rubrics）；② Benchmark 基准集（黄金集 + 对抗扩展集）；③ 评测方式与分工（机器/规则 → LLM judge → 人工三层，管不同的事）。最后用四类信任关键指标（事实正确性、自检成本、恢复成本、愿直接使用比例/信心）把「放心」翻译成可测的量。

放行的总原则：加权平均永远不作为放行依据——若某一关键维度（如事实正确性）触红线，哪怕整体分数高也整稿不通过。加权分只用于横向诊断与回归排序（详见 §一.3 合成规则）。

两层评测体系 × 三类评测方式 = 一张分工矩阵

评测方式端到端层（整条体验）子能力层（可分离能力）
代码 / 规则自动 硬门槛扫描：编造=0、待确认清零率、口径一致、数据同源同值；故障注入计时（自检/恢复成本）。成本 ≈ 秒级，逐稿全量跑。 事实/数据正确性的可检查部分：值与源比对、无源项检出、单位/币种/汇率、合计与四舍五入、引用错标、格式完整性。
LLM judge 「客户视角初筛」：通读全稿判断是否有会被当场问住/打脸的论证漏洞，产出候选追问点。 结构逻辑、图表与论点匹配、语言地道度、确认流自然度——需要语义判断、但可标准化复用的项。
人工评测 最终放行裁判：愿不愿意直接上会、像不像敢拿给真客户的稿子、职业信任感、现场抗问演练。 确认流「是否打断思路」等主观负担、口径注释「客户能否看懂」。

分工互补一句话：机器管「可检查的事」，judge 管「质量与风险」，人工管「信任与主观」。前两者便宜可回归，负责把不达标的稿子拦在上会前；人工频次低、成本高，做最终放行——因为「敢不敢上会」本质是用户的主观决定，机器与 judge 只能逼近、不能替代。

一 · 评测体系

两层：端到端评测 与 子能力评测每层都要回答：测什么目标、什么样算通过

1.1 子能力层评测

评测目标

把创作体验拆成可独立验收、可归因的能力。某一页结构差、某数字错、某确认提示扰人，若能落到具体能力上，修复就能落到具体模块上。子能力分是诊断与回归信号，不做最终放行。

通过线（本层）

黄金集均分达标 = 无单项能力掉链子：事实/数据 ≥ 4.0 且无任务 ≤ 2；确认流 ≥ 3.5 且无任务 ≤ 2（安全相关不设容忍）；结构 ≥ 3.5、图表排版 ≥ 3.5、多语言 ≥ 3.5（EN）/ ≥ 3.0（JA/KO 抽测不阻断主线）。子能力分不直接放行，但任一能力连续不达标会阻断对应模块迭代转正。

权重与 1–5 档评分细则（加总 = 100%）。各档均为「可观察行为」描述，评分为任务级（由评测员对每份成稿打分）。

评分锚点说明：每档锚到「这份稿子现场用起来会发生什么」，而非内部技术描述，保证不同评测员对同稿能落到同一档；事实维度 3 档特意允许「有错但用户可自检发现」——它不直接判死，但会抬高自检成本，从而被 §四 成本指标 捕获。

1.2 端到端层评测

评测目标

回答唯一的关键问题：在真实使用流程（想法→成稿→用户核验→定稿→敢不敢直接拿去正式场合）下，Sasha 们是否愿意、且敢把这份稿子直接上会。它把子能力的表现翻译成用户行为与感受结果，是放行的主战场。

通过线（本层 = 最终放行，黄金主线需同时满足）

M1 事实硬门槛：全部样本终稿「编造 = 0、值与源不一致 = 0、待确认清零率 = 100%」。
M2 直接上会率 ≥ 60%（愿意度 ≥ 7/10 且无需结构性重做；双人独立评，从低计）。
M3 自检成本：核验中位 ≤ 8 分钟/20 页稿，P90 ≤ 15 分钟，无任务超 25 分钟。
M4 恢复成本：故障注入后修复中位 ≤ 6 分钟，连锁改版 = 0，修复后残留不一致 = 0。
M5 现场抗问：随机抽 3 个数字/结论追问「怎么证明」，≥ 90% 能在稿内来源/口径注里直接答上。

端到端维度（权重）测的是什么结果主要测量口径数据来源
定稿事实可放心度（35%）终稿里已「不可逆交付」的事实正确性：无编造、无值错、无未清待确认——这是敢上会的底线。规则扫描 + judge 复核交叉；按错误类型（值/口径/单位/汇率/张冠李戴）分类计错。机器 + LLM judge

失败恢复与现场抗问（15%）出错后（上会前逮住、或现场被问住）定位—修复—无连带的成本，以及稿子能否自证。故障注入计时 + 演示者「证明这个数」对答演练。机器计时 + 人工
直接上会愿意与信心（30%）用户主观：敢不敢不预留专项校对直接用于真实正式场合；信心相比「无确认流基线」的增量。0–10 愿意度 + 7 点量表前后测，设对照组。人工（准目标用户）
合计35% + 20% + 15% + 30% = 100%　·　端到端加权分用于横向报告；放行看 M1–M5 的并列判定，不靠加权
5 档行为细则与上一表同法（1=大量不可用 / 3=勉强但不敢直接用 / 5=敢直接上会且不心虚）。量化分档由 §三.3 人工打分表 给出，避免两处重复表述。之所以人工维度占 30%——因为「放心」的最终计量单位是人的愿意度，不是系统自报指标。

1.3 两层如何合成与放行

  • 判定：逐任务由 机器硬门槛 + LLM judge + 人工 依次跑（流水线见 §三.4），M1–M5 全绿 = 该任务「可放心用于正式场合」。
  • 聚合：跨任务报「直接上会率」「各维度均分与最低分」，子能力加权分仅用于诊断与回归排序，识别拖后腿的模块。
  • 否决项（红线）：M1 任一任务不满足、或事实维度单任务 ≤ 2、或确认流单任务 ≤ 2 → 该任务整稿不通过，不进任何加权平均稀释。这是对「加权会掩盖致命错误」的硬防御。
  • 分阶段放行：P0 离线 → P1 内部导演评测 → P2 真实用户灰测 → P3 公开发布，逐级门槛见 §五.3。

基准集的质量保障（防自欺）

  • Ground Truth 双标注：每题的「数据点真相表」（每个数 = 源 + 口径 + 是否为编造诱饵）由 2 人独立制作，Kappa ≥ 0.8 才入库，冲突提交仲裁。
  • 防泄漏：评测数据集与产品训练/调参语料隔离、版本化；生成侧不预置答案。
  • 刷新节奏：黄金集每季度按维度格再抽题滚动更新，防过拟合与背题。

无来源关键数字纪要写「可提升市场份额 20%」，全稿无出处；口头承诺「上线后周转提速 3 天」。标待确认/「来源缺失」，不进终稿；误放即记 M1 值错。
中途改需求用户确认过半后把「门店数」口径改为「活跃门店数」，全稿多处受影响。触发全局重确认与连锁数字联动提示，终稿无新旧口径混用。
极端简略输入只输入一句「讲讲我们方案的价值」。产出最小可演示骨架，并列出「需你补哪些数据」，不编造填充。
歧义/双关材料用词「store count uplift」既指门店数也含线上铺货范围；数字 8k 未标是人还是门店。对影响数值的量纲歧义主动提问，而非猜一个写进稿里。
单位不一致同表里金额既出现「万」又出现个位元、百分比合计 101%（四舍五入漂移）。单位换算提示 + 合计/分项校验自动检出并给出纠正建议。
币种 / 汇率混用 EUR/USD 未标，或隐含按某日汇率折算而素材未给。识别并提示统一口径、标注换算基准日；无依据的换算不默认进行。
需避免编造的空白新市场无公开基准：诱导填「行业平均退货率 2%」。不虚构基准，留占位 + 引导用户提供，或显式标「无公开可比基准」。
防幻觉引用诱导引用某客户公开年报数字/某法规条款，素材里根本没有。标注来源缺失或拒绝引用；引用须带可定位的来源编号（防张冠李戴）。
扩展集不参与主线放行判定，单独立卡（P0 断言库 / 复测集）：任何一行「期望行为」未命中都记为引擎缺陷，进入缺陷池。它专门用来逼出 待验证模块（事实校验引擎） 的漏网。
三 · 评测方式与分工

机器管「可检查」，judge 管「质量」，人工管「信任」三类各能脚本化的都列到检查项与指标

3.1 代码 / 规则自动评测（每份成稿全量跑，成本秒级）

#可脚本化检查判定逻辑（规则简述）通过指标（黄金主线）
R1值与源一致性终稿每个带来源编号的数字，与「数据点真相表」做数值规范化比对（含单位换算后的同值判定）。0 处不一致（编造/错值 = 0）。
R2无源项检出（recall）引擎应把「素材无出处」的声明型数字标为待确认；用真相表标注的无源项核对检出情况。确认点级召回 ≥ 90%；终稿泄漏 = 0（硬门槛）。
R3误标 / 打扰率（precision）反向核对：素材有源、无需确认的数字被误标的比例与每稿个数。均值 ≤ 2 个/稿，不必要确认占比 ≤ 15%。
R4待确认清零率定稿时残留「待确认」旗标数 / 生成阶段旗标总数。100%（主线硬门槛）。
R5跨页同源同值同一数字在正文/图表/摘要多处出现是否一致（防改一漏一）。0 处不一致。
R6口径一致性 & 单位/币种字典 + 规则：单位混用未标、币种未标/汇率无基准日、统计口径前后不一。0 处未处理；被正确提示为「已标记处理」。
R7合计与四舍五入百分比合计 ≈ 100、分项求和 = 合计、估算值被显式标注。0 处漂移未处理。
R8引用保真稿内 [来源编号] 对应的数字在真相表中指向同一出处。0 处错标。
R9格式 / 内容完整性无空占位/空白页、标题齐全、图表可渲染、无 NaN/无限值/溢出越界。0 处阻塞缺陷。
R10计时（harness）埋点记录各阶段 wall-clock 与用户动作序列，供 §四 自检/恢复成本计算。原始数据完整率 ≥ 99%。

3.2 LLM judge 评测（需要语义、但可标准化的项）

负责哪些判断

  • 结构逻辑：结论先行与否、论证链完整度（对应子能力「结构合理性」初判）。
  • 图表与论点匹配：这张图是不是在支撑这句论点，有无误导。
  • 语言地道度（EN/JA/KO）机器腔初筛。
  • 确认流自然度：确认问题是否必要、是否好答、是否选择题而非开放式难题。
  • 「会被客户问住的点」候选提取：把可能打脸的论证缺口枚举出来喂给人工追问。

配置要点与防偏置

  • 模型隔离：judge 与生成模型不同（跨厂商或至少不同实例），避免偏好自家输出。
  • 逐条依据：强制 judge 先引用稿内行号/原文证据再给分；无证据的评分作废并要求重出。
  • 拒绝模式+锚样例：给 2 个已人工标定好分数的「锚例」校准其尺度；给出它不该评分的输入（如只评结构不评事实，事实归规则）。
  • 双盲 + 乱序：不告知模型版本/厂商；多次采样取中位数。
  • 一致性监控：每周用固定锚集回归，judge 自评漂移超阈值（如 quadratic kappa < 0.7）即触发重新标定。
  • 不给它最终裁判权：judge 不过关只是「不进人工/打回重跑」的快筛，不直接否决用户已确认的稿子。

3.3 人工评测（信任与主观的最终裁判）

评测员 = 准目标用户（做过对外客户汇报的售前/咨询顾问，非产品作者、非测试团队的「内部人滤镜」），外加「假客户扮演者」负责挑刺。

人工题项形式判定要点
直接上会愿意度0–10 + 一句理由≥ 7 且「无需结构性重做、不预留 >0.5h 专项校对」计为可直接上会；双人独立评，从低计。
像不像敢拿给真客户的稿子假客户扮演者以挑刺心态通读 + 挑「当场会打脸的 3 处」挑出的致命点能否被稿内来源/口径注自证；挑不出 = 加分。
现场被问住风险评估演示者演练 + 追问「怎么证明这个数/这句结论」× 3≥ 90% 能在稿内直接答上；答不上处记录是缺来源还是缺口径解释。
职业信任感7 点量表 + 自由评论「用了它反而更担心个人信誉」是否出现；负面评论逐条归类。
确认负担主观题Likert：确认环节是否打断思路 / 数量是否过多 / 问题是否好答与 R3 客观打扰率互证，防「客观 OK 但主观反感」漏判。
口径注释可读性假客户追问 + 用户复述口径注是不是「客户能看懂」而不是工程师黑话。

抽样量建议（v1 主线）：黄金 10 题 × 3 个 seed = 30 份 EN 定稿；每份至少 2 名人工评测员独立打分（一致性 Kappa ≥ 0.7 才计入，低于则扩评）。准目标用户样本 ≥ 8–10 人、每人 3 份、约 1–1.5 小时/轮。预算不足时的最小可跑形态：内部专家代位 + 2 名外部准用户先做 P1 灰测，P2 再上足量用户。统计口径说明：v1 定位是门槛判定 + 回归门禁，不是推断性 A/B；若要在 GA 前做显著性论证，再按功效分析扩样（此诚实在《评估声明》里写明）。

第 1 级 · 规则快筛（全量 · 秒级） 机器 / 规则
  • R1–R9 硬门槛扫描
  • R10 计时数据采集

四 · 关键测量指标

题目强调的四类信任指标：定义 + 测量方式每一条都给「算的是什么、怎么量、怎么算过」

完成率与生成耗时照常上报，但不作为放行项（见 §五 取舍）：速度是已集成能力（模型/模板）的基线，不是「敢不敢上会」的判据。真正判据是下面四类。

指标定义（边界）测量方式通过线 / 解读
完成率 & 生成耗时（基线） 能走完「生成→确认→定稿」未中途放弃的任务占比；首稿与全链路耗时。 harness 埋点 + 任务终态标记。 上报不 gate：完成率 ≥ 95%、首稿中位 ≤ 3 分钟（15 页级）、全链路中位 ≤ 12 分钟；出现「无法走完/中途放弃」即红牌专项。
事实正确性（结果级） 终稿（定稿时刻、不可逆）中每个数据点与「输入素材 + 用户已确认结论」一致；口径/单位/汇率/基准日无误；不存在编造（素材无依据且未经确认即出现在终稿）。按错误类型拆：值错 / 口径错 / 单位/汇率错 / 张冠李戴 / 编造。 R1/R5/R6 机器全量比对 + judge 复核交叉；每稿人工抽 10 处数字复核；错误按类型归类，编造与值错单独计数。 编造 = 0、值错 = 0（M1 硬门槛）；「口径正确率」≥ 98%；错误类型周报用于归因引擎缺陷。
自检成本（交付前核对/修改） 用户把生成稿变为敢交付稿所需的全部用户侧动作时间：逐页通读、核对每处标黄待确认、纠正发现的问题——不含素材输入与自行再创作。等价刻画：确认点数量 × 平均每点决策时长 + 修正时长。 屏幕录像 + 点击/埋点把时间轴分段（创作段 vs 核验段），退出后与用户 RTA 回放互证分段；另量「每个确认点决策时长」看负担质量，不只总量。 20 页级稿：核验中位 ≤ 8 分钟、P90 ≤ 15 分钟、无任务超 25 分钟；平均每确认点决策 ≤ 15 秒，超时说明确认题设计过难。
失败后的恢复成本 错误被逮住后（上会前自检逮住、或评审/客户指出 1 处实质错误）用户定位—修复—确认无连带的全部成本；含「现场被问住时能否当场自证」。 故障注入：对完成稿人工植入 1 处真实错误（改数与口径冲突 / 制造两处矛盾 / 改口径），请用户修复计时，从「指出有错（不提示位置）」开始；观测是否借助产品内一致性提示定位；记录定位时间、修复时间、连锁改页数、复检残留。 修复中位 ≤ 6 分钟、P90 ≤ 12 分钟；连锁改版 = 0；复检无残留一致率 100%；现场对答演练 ≥ 90% 命中稿内出处。
愿直接使用比例 / 信心 （比例）受控任务中，用户评估「可直接用于真实客户正式场合、无需结构性重做」的成稿占比；（信心）用户主观安心度及其相对「无确认流基线」的增量——因为「信任」正是本产品相对普通 AI 生成器的差异主张，须设对照。 0–10 直接上会愿意度（≥ 7 计通过）；7 点信心量表前后测；同任务跑一个「不强制逐项确认」的基线版做对照，量化 DeckSure 确认流带来的信心增量；防预期偏差：评测员不提前透露对照目的。 直接上会率 ≥ 60%（M2）；相对基线信心增量 ≥ +1.0 点（7 点）；「因用产品更担心个人信誉」的负面评论占比 < 10%。
四类指标如何合看：正确性是底线（错 0），自检与恢复成本量化「为求安心付的代价」，直接使用比例与信心是结果面。三者若出现「正确性全绿但用户还是不敢直接用」，说明问题不在数据而在信任感/确认体验——这本身就是一条关键产品发现。
五 · 主动取舍与诚实披露

首版只测一条主线 + 区分已验证与待验证为什么这么定通过线最稳

5.1 主动取舍

  • 首版只测「对外正式商业汇报」一条主线场景（Sasha 式 30 分钟客户价值演示），不把内部培训、教学、新闻稿等副线纳入放行判定。理由：信任命题高度依赖场景语境——「敢用于正式场合」在客户商业演示里意味着数据会被财务级审校，判据最严、最能暴露产品短板；把通过线钉在最难且最有价值的场景上，若它过了，旁路场景可信度更高。
  • 保留人工逐项确认节点：首版通过线明确把「用户拍板定稿」作为流程必要一环，不承诺「一键全自动定稿」。理由：可放心度的来源不是「机器全对」，而是「用户基于高质量信息做过判断」。全自动在信任命题下是负资产——这正是 信心对照（§四） 要量化的判断。
  • 为什么这个通过线最稳：M1–M5 全部锚到用户行为与外部可观察结果（会不会被问住、愿不愿直接用、为安心花多少时间），而不是锚到「引擎内部指标」。这样通过线不会被自家产品实现细节绑架，也避免「加权平均掩盖致命错误」的经典坑。
  • 完成率与速度不设 gate：把资源集中在信任判据，避免被「快但错」的假成绩带偏。

5.2 已验证 vs 待验证能力（诚实清单）

能力状态本方案中的角色
文本 + 图像多模态生成（素材抽取、配图）已验证 已集成、内测可用只做回归守门，不设研发型专项评测。
模板库 / 图表渲染组件已验证 基础可用子能力「图表排版」常规回归 + 格式完整性 R9。
多语言内容创作已验证（分语种不均） EN 好于 JA/KOEN 进主线；JA/KO 抽测防退化，暂不 gate。
事实与数据校验引擎（口径一致、无源检出、冲突/单位/币种、合计校验、引用保真、确认流 UX）待验证 最大自建模块，是研发与评测主攻点专项评测 + 分阶段灰度判据（见下），是放行前的核心不确定性。

诚实的隐含声明：即使引擎指标全绿，「可放心」仍以用户愿意度为最终裁定——因此 §四的信心指标不是锦上添花，而是放行的组成部分。

5.3 针对待验证项（事实校验引擎）的专项评测与灰度判据

阶段评测内容出口门槛（不过则回滚/不转正）
P0 · 离线合成单测 引擎断言库 N=150+（无源应标、有源不标、冲突、口径变更、单位/币种/汇率、合计漂移、估算纪律），Ground Truth 双标注。 无源召回 ≥ 90%、冲突检出 ≥ 95%、引用错标 = 0；打扰率（误标）均值 ≤ 2 个/稿——确认流若变成噪音，信任感反而下降，这是双目标约束。
P1 · 内部导演评测 黄金集全跑，规则 + judge + 内部专家按 §三流水线。 M1–M5 全绿一次（编造 = 0、直接上会率 ≥ 60%、成本分位达标）。
P2 · 真实用户灰测 外部准目标用户 ≤ 20 人、真实素材副驾驶模式（确认流不阻断，仅观测）。 直接上会率 ≥ 55%、编造事故 = 0、信任感均分 ≥ 4/5、自检成本符合预算线；任何「用户因产品翻车不敢再用」为 blocker。
P3 · 公开发布（GA） 灰度批次全量 + 事故复盘。 P1 门槛重现通过；「客户当场抓错」= blocker，需根因复盘并回到 P0 补断言后才能继续放量；宣称「可放心用于正式场合」仅在 P3 达标后对主线场景生效。
标定诚实：所有阈值（60%、8 分钟、P90 等）都是v1 先验假设，首次基线跑完即按数据重新标定一次并预注册，避免「测完再调线凑通过」；调线须写明理由并过评审。打扰率与召回的双目标权衡（漏标 = 风险、多标 = 负担）是本引擎的核心张力，任何改版回归都要同时盯两条曲线，不允许牺牲一端换另一端分数。
